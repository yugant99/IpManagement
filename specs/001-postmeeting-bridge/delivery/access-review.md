## Authority and response boundary

`access.py` validates an individually provisioned 64-character lowercase hexadecimal bearer against its SHA-256 digest, enabled state and UTC expiry. It derives the principal, effective roles, selected permitted domain and configuration revision/digest. Requester, Operator and Approver inherit Viewer; Platform admin does not inherit domain data or approval authority. The evidence coordinator is an explicitly named, roleless, domainless principal with only fixed evidence operations. Source/scope pairs map to one domain, and coordinator grants equal source mappings. `app.py` requires that equality to cover every registered synthetic feed pair, validates mapping against persisted scope domains, and checks authority again in transaction write helpers. Ordinary reads now require effective Viewer; domain mutations require their operation role and selected domain. Body actor fields are compatibility assertions against the trusted principal, not authentication.

The middleware authenticates before checking the pinned configuration revision and digest. It returns generic 401 for invalid, disabled or expired credentials; authenticated stale pins return 409 `ACCESS_CONTEXT_STALE` before protected data or mutation. Authenticated responses include current configuration headers. Browser tokens remain in memory; protected requests and blob downloads carry bearer, selected domain and configuration pins. The client rejects responses after session epoch or configuration changes, including after JSON/blob reads, and remounts protected state on principal/domain change, logout or revocation.
