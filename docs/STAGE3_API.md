## Evidence and calculations

Evidence lane files: `imports.py`, `evidence.py`, `calculations.py`, `rules.py`, `reconciliation.py`. Existing import transaction/receipt/replay API remains. DHCP records use typed normalized half-open lease intervals in `source_records`; raw rows and metadata remain immutable. Intended-inventory uploads are staged, never promoted, and do not participate in observation selection. Receipts use `application_status=complete|partial|staged`; exclusive accepted/rejected/duplicate counts retain the original contract. A new import also stores a system audit event in its transaction, including counts, coverage and source identities. Identical replay adds neither rows nor audit effects.

`evidence.active_dhcp_claims(connection, scope_id, family, address, clock_text)` returns `claims` plus `unknown_reasons`; allocation reads current eligible evidence through this helper, never saved findings. Missing DHCP cannot establish availability: static availability comes from the explicitly authoritative local intended ledger. Ambiguous/stale/incomplete observations are exposed conservatively.

`calculations.calculate_pools(connection, views, clock_text)` supplies the only occupancy/p95/forecast implementation. Saved `run.calculations` contains pool/scope/prefix identity, decimal-string capacity and occupied counts; current occupancy; 720 hourly history samples and p95 eligibility; forecast status/basis/daily p95; coverage, record references and limitations. All 720 samples must be eligible for 30-day p95. Forecast uses 14–30 consecutive complete days and shared OLS; missing samples stay null. Pool or prefix version above 1 conservatively invalidates historic fits, even after metadata edits; later imports do not automatically recover a fit. Complete current exhaustion remains known independently of historical consistency. Inactivity considers all lease intervals within the intended prefix, including excluded/out-of-range claims; occupancy and denominators remain assignable-only. This bounded history limitation needs future historical authority modeling.

Existing G13 findings retain their semantics. ## Inventory and fixed workflow

These routes are coordinator-authored wiring; dependent module integration is tracked in the stage report. All mutation payloads use named actor IDs, not caller-supplied roles. `GET /api/actors` returns a plain array. `demo-requester` is Access Planning; `demo-approver` is Network Operations. Both may request/operate their queue; only the approver may approve and edit inventory. These are demo identities, not login or tenant security.

- `GET /api/prefixes/{id}/edit-context`, `GET /api/prefixes/{id}/child-preview?prefix_length=N&limit=10`, `POST /api/prefixes`, `POST /api/prefixes/{id}/edit`: validated child creation/safe edits with expected prefix/parent and baseline versions. Child preview counts are strings and never enumerate IPv6 hosts. Bounds changes refuse children, pools or assignments. Mutations preserve origin, change current versions and append audit atomically.
- `GET /api/workflow`, paged `GET /api/allocation-requests`, `POST /api/allocation-requests`, `GET /api/allocation-requests/{id}`, `POST /api/allocation-requests/{id}/decision`: one static local pool. Request fields are actor/key/pool/exact candidate/reviewed pool and baseline versions/owner/purpose/reason, optional superseded request. Decision fields are actor/action/reason and optional `simulate_failure`. Server checks exact candidate, versions, current intended assignments and eligible contradictory observations in the allocation transaction. No self-approval; repeat same request/decision returns existing effects; changed retry payload conflicts. Pending requests do not reserve addresses.
- `GET /api/audit?request_id=&subject_id=` and `/api/audit/export`: stored events and CSV. Success allocation and audit commit together. Root writes failure audit after rollback when possible; errors report `audit_recorded=false` and a visible message/log if the failure audit cannot be stored.
- `GET /api/exceptions`, `POST /api/exceptions/{id}`: independent queue state with actor/version/action/reason and recipient actor for handoff. `workflow.sync_exceptions(connection, run)` follows the immutable run insert in the same transaction and creates only unseen anomaly keys. Acknowledgement never rewrites evidence state. The source implementation can record fixed fictional team transfer and recipient acknowledgement; actual RFP-081 evidence remains unobserved.

## History and exports

`GET /api/run-comparison?before_run_id=&after_run_id=` compares two chronological immutable runs by rule/scope/subject. Missing, unknown and not-applicable outcomes do not resolve an old anomaly. `GET /api/runs/{id}/export` returns pinned actual JSON, including saved calculations, selected receipts and filters. Scope/rule/severity/state filters narrow findings; scope narrows pool metrics; the exported overview explicitly retains full-run totals.

`GET/POST /api/report-preset` reads/saves one report preset with actor/reason/name/run/filters/columns; `/api/report-preset/export` exports its selected findings as CSV with run/filter headers. Supported columns: run_id, rule_id, scope_id, subject, severity, evidence_state, explanation, proposed_action. CSV text is protected against spreadsheet formula interpretation. Audit export uses stored audit rows. There is no arbitrary report builder or scheduled report transport.

RFP-043 import-triggered reconciliation and RFP-068 scheduling are not implemented at this checkpoint. Explicit run creation remains the trigger. PART6_READY remains no; portable state and recipient evidence are lead-owned gates.
