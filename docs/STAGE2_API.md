## Imports

`POST /api/imports` accepts JSON bytes, bounded to 10 MiB and 10,000 records before mutation. Only `ipam-synthetic-v1` routing and policy envelopes from `fixtures/SCHEMA.md` are supported. Inventory/DHCP/oracle envelopes return 422 without mutation; richer inventory is not promoted. Policy envelopes declare `source_kind: inventory_policy`, `source.authority: intended_policy`, and explicit per-scope `coverage` snapshots with equal start/end at the fixed clock, plus `effective_from_at <= clock`. The internal stored kind is `route_policy`. Routing envelopes retain `source_kind: routing` / authority `observed` and interval coverage. Policy applies only to existing prefix/scope IDs; an explicit policy is required to assert a missing route.

Importer function: `import_envelope(connection, body: bytes) -> (receipt: dict, replay: bool)`. Caller supplies a writable connection with `BEGIN IMMEDIATE` already open, commits on success; importer does not begin/commit itself. Complete accepted envelope with no accepted rows is still retained and participates in latest-source selection; row failures make effective completeness false. Duplicate rows do not inflate acceptance. Identical row ID/reference+payload repeats are duplicates; contradictory same identities reject all ambiguous rows. Canonical normalized-envelope hash includes rejected values, with known valid timestamp fields normalized to UTC milliseconds and raw timestamps retained in stored input. Replay returns the original receipt without a new ingestion sequence; different content for the same identity is 409. A source ID cannot change kind. Envelope clock must equal seeded demo clock.

Response is the receipt itself, HTTP 201 for new import, 200 for replay; header `X-Import-Replay: true|false`. Receipt fields: `id`, `sequence`, `source_id`, `source_run_id`, `source_kind`, `ingested_at`, `demo_clock_at`, `application_status` (`complete` or `partial`), `input_rows`, `accepted_rows`, `rejected_rows`, `duplicate_rows`, `synthetic: true`, `coverage` (normalized coverage plus effective completeness), `limitations: string[]`. Counts sum exactly to input. Scope coverage rejects unregistered scope at envelope boundary; row rejects remain visible. An invalid/future policy effective_from_at is a retained partial batch with all rows rejected and effective completeness false, even for zero records; it replaces the prior view and yields unknown. Structural envelope errors (including unknown coverage scope) return 422 with no accepted batch. Policy coverage is explicitly declared, including when records are empty or omit a prefix; invalid/unscoped rows conservatively make all declared scopes incomplete. The latest policy snapshot replaces the previous snapshot for its declared scopes; omitted prefixes become unknown. Empty policy record arrays are permitted with explicit coverage.

`GET /api/imports?limit=50&offset=0` returns `Page<Receipt>`, newest sequence first. `GET /api/imports/{id}` returns saved receipt. `GET /api/imports/{id}/records?status=rejected|accepted|duplicate&limit=50&offset=0` returns a page of `{id,batch_id,row_number,source_record_id,status,reason,raw,typed}`. `GET /api/source-records/{id}` returns one such record. Original envelope is available at `GET /api/imports/{id}/envelope`.

## Runs and evidence

`POST /api/runs` (no body) runs the single rule at the seeded fixed demo clock. Synchronous/nonblocking process lock returns 409 `RUN_IN_PROGRESS` for a concurrent trigger. Import and run transactions are explicit. Creation returns full saved run with HTTP 201. `GET /api/runs?limit=50&offset=0` returns pages of run summaries (full run minus findings). `GET /api/runs/{id}` returns full saved run.

Saved run fields: `id`, `created_at` (wall clock), `demo_clock_at`, `ledger_version`, `rule_id: missing_expected_route`, `rule_version: 1`, `synthetic: true`, `selected_batches: Receipt[]`, `overview: {total,anomalous,healthy,unknown,not_applicable}`, `findings: Finding[]`.

`GET /api/runs/{id}/findings?scope_id=&evidence_state=&limit=50&offset=0` returns page from that saved run. `GET /api/runs/{id}/findings/{finding_id}` returns the exact saved finding. No latest-run alias can alter a pinned detail.

Finding fields: `id`, `run_id`, `rule_id`, `rule_version`, `subject` (snapshot: `id,scope_id,scope_name,family,cidr,version,origin`), `severity: high`, `evidence_state: anomalous|healthy|unknown|not_applicable`, `explanation`, `input_references` (objects with `kind`, optional `batch_id`/`record_id`, `source_id`, `source_run_id`, optional `source_record_id`), `evaluated_window: {kind: instant,start_at,end_at,interval_convention: '[start,end)'}`, `limitations: string[]`, `proposed_action`, `policy` (normalized policy or null), `coverage` (selected routing receipt coverage entries plus batch/source identity).

Latest ingestion sequence per source/scope replaces earlier evidence, including partial batches. Do not stitch batches or fall back. More than one policy source or routing source for a scope is explicit unknown authority ambiguity in this bounded path. Route presence requires matching scope/family, active half-open validity and fresh applicable source view (covered end at most five minutes before clock, never future); positive observations may establish presence in incomplete views. Missing routes require complete applicable evidence and explicit exact/covering policy. Fresh covered end may equal clock; it is an assertion cutoff, not route expiry. Missing/stale/partial/invalid policy or routing evidence remains unknown. A false expectation is not_applicable, not evidence of network health. No automatic resolution/history comparison, no safe-reclaim or live-network claim.

No tests, build/type checks, app execution, browser checks, containers or deployment are authorized. Source inspection does not demonstrate behavior.
